# 产品路线图

路线按可复现结果推进，不按插件数量或虚构用户数推进。

## `0.1.0-alpha`｜公开首发

完成标准：

- 中文首页、模板、合成示例、Bases、Canvas、浅色和深色主题可直接使用。
- Release ZIP 从零解压即可打开，首页默认指向 `Home.md`。
- 自检覆盖链接、隐私、许可、社区插件缺失、工作区与发行包内容。
- Codex 按 `AGENTS.md` 完成 R0 只读和 R1 隔离草稿合成任务。
- LWC Strict Review 在临时发行包副本中完成“建议 → 审核 → 冲突阻断 → 接纳”测试，不改正式样例。
- README、双语入口、Security、Contributing、Issue/PR 模板和 CI 就绪。

## `0.2.0`｜发布后修正

只处理公开发布暴露的阻塞：

- 首次打开、链接、字体、主题、模板和跨平台兼容问题。
- 可复现的 Agent 越权、上下文过宽和 Strict Review 失败。
- 记录下载、Issue、自然贡献和复现环境；不增加跟踪脚本，不上传 Vault。

进入下一阶段至少需要三个独立公开信号之一：可复现 Issue、外部 Fork/贡献、含真实任务的使用说明。Star 只作方向信号。

## `0.3.0`｜可选 Packs

候选包必须有真实公开问题支持，并写明权限、依赖、卸载和降级：

- Research：来源卡、研究项目、严格审核示例。
- Creator：内容项目、素材与发布前检查。
- Project：跨笔记行动视图；优先使用核心 Bases。
- Visual：额外 Canvas、Bases 和主题布局。
- Strict Review：LWC 的来源绑定、精确 Diff 与冲突阻断。

没有公开问题证据的 Pack 不开发。Core 始终不强制社区插件。

## `1.0.0`｜稳定模板

- 升级不覆盖用户内容；受管文件清单、dry-run 和回退契约稳定。
- 已验证平台、Obsidian 版本、Agent 宿主和已知限制清楚。
- 发布节奏、维护责任和安全响应方式稳定。
- Strict Review 是否继续依赖 LWC，由公开采用和维护成本裁决。

## 维护指标

- 首次成功：发行包是否能打开 Home 并完成捕捉—找回闭环。
- Agent：R0/R1 合规率、越权写入数、草稿可接纳性。
- 审核：每个接纳结果的审核分钟、冲突阻断和误阻断。
- 维护：失效链接、升级冲突、必需社区插件数和发行包可复现性。

## 明确不做

- 不内置模型、聊天界面、向量数据库、账号或云同步。
- 不为截图默认安装社区插件全家桶。
- 不把私人 Vault、聊天记录或身份数据用作公开示例。
- 不把 LWC 的工程术语暴露为 Qingyan Vault 的日常信息架构。
- 不在没有第二个独立消费者前拆分公共 review-core。
