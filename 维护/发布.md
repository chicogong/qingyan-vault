# 开源分发与发布检查

维护状态见 [交接](交接.md)，当前任务见 [路线](../规划.md)。本页保留每次发布的检查要求，不重复启动早期立项或首发调研。

## 仓库

- 名称：`chicogong/qingyan-vault`。
- 定位：中文优先、英文可发现的 Agent-native Obsidian Vault。
- 分发：GitHub Template Repository + 每个 Release 的干净 ZIP。
- 许可证：MIT；内置 Border 主题保留原 MIT License 和归因。
- 核心承诺：开源包完整可用，不用缺少关键插件迫使用户购买升级。

## 发布检查

找不到测试用户不是虚构验证的理由，也不应无限阻塞发布。首发采用“维护者深测 + 公开 Alpha”模式：

1. 维护者从干净 ZIP 开始，验证首页、捕捉、搜索、项目、模板、主题和降级路径。
2. 用合成来源验证 Agent R0 只读、R1 隔离草稿和可选 Strict Review；不得读取私人 Vault。
3. 对失效链接、冲突修改、来源漂移、关闭 CSS、无社区插件和重复打包做故障注入。
4. 明确已验证环境和未知边界，确定版本、精确提交及制品；经确认后再发布，不能将候选 ZIP 当作已发布版本。
5. 发布后以匿名下载、可复现 Issue、Discussion 和自然贡献作为产品信号，不要求登录、埋点或上传 Vault。

## 源码与发行包

源码仓库可以包含 GitHub 治理、测试和打包工具；Release ZIP 必须排除：

- `.git/`、`.github/` 治理文件、`dist/` 与本地缓存；README 使用的 `.github/assets/` 截图保留；
- 白名单 `qingyan-homepage` 以外的插件、插件运行数据、同步状态、移动端工作区和机器私有状态；
- 凭据、绝对路径、私人内容和未经许可的第三方资产。

发行包保留一份脱敏的 `.obsidian/workspace.json`，只用于首次打开 `Home.md`。它不得包含本机路径、搜索历史、私人文件名或临时标签页。

## `.obsidian` 边界

提交并分发：`app.json`、`appearance.json`、核心插件配置、Daily Notes、Templates、Bookmarks、经过许可审查的主题、Qingyan CSS、第一方 `qingyan-homepage` 插件和脱敏首页工作区。

不提交：白名单之外的插件代码、缓存、同步状态、工作区移动端状态、插件运行数据和个人快捷状态。可选 Pack 暂不排期；恢复时必须可卸载，并能降级成可读 Markdown。

## LWC 关系

在本模板内，LLM Wiki Canvas 仅是可选 Strict Review 引擎，负责来源绑定、隔离草稿、精确 Diff、冲突阻断和人工接受/退回；不复制其源码、不拆新的公共 review-core。LWC 独立产品的路线不由本仓定义，本仓文档不宣布其冻结。

## 发布 Stop 条件

- 发现私人或第三方受限数据、凭据、机器绝对路径。
- 干净 ZIP 无法打开首页或通过自检。
- Agent 可在未授权时修改正式知识。
- 必需功能依赖不可审计的社区插件或网络服务。
- 第三方许可、名称、维护边界或回退路径不清楚。

## 商业化边界

核心 Vault、格式、Agent 协议、主题基础、自检和迁移出口保持开源。未来可收费的是团队定制、迁移实施、培训、托管更新、专项主题和经审计的 Pack；不出售用户数据，不用私有格式制造迁移成本。
