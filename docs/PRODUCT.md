# 产品主旨

## 一句话

**让人和 Agent 从同一个本地 Markdown 工作区开始：人保留判断权，Agent 承担整理工作，知识不会因为换模型、换工具或换电脑而丢失。**

## 它解决什么问题

普通 Obsidian 模板通常只解决目录和外观；Agent Vault 通常先要求用户理解 Skills、记忆、Git、向量检索和复杂治理。两者之间缺少一个真正能在一分钟内开始、同时又不会把未来堵死的中文起点。

Qingyan Vault 补的是这一层：

```text
人的快速捕捉 → 来源与长期知识分层 → Agent 隔离草稿 → 人工接纳 → 周期回顾
```

## 三个承诺

1. **一眼能懂。** 中文路径、真实示例和 60 秒闭环，不先教术语。
2. **Agent 有用但不越权。** Agent 默认只读，草稿与正式知识分离，事实与推断分离。
3. **随时能走。** Markdown 是事实源；Bases、Canvas、主题和 Agent 适配都是可替换层。

## 面向谁

- 想开始个人知识库，但不想先研究几十个插件的人。
- 想让 Codex、Claude Code、WorkBuddy 等工具整理知识，但担心误改和上下文漂移的人。
- 想建立可公开、可复制的团队知识模板的个人创作者和小团队。

## 它不是什么

- 不是把所有生活数据塞进一个 Personal OS。
- 不是自带模型、聊天界面或向量数据库的 AI 应用。
- 不是社区插件全家桶，也不承诺替代任务管理、日历或同步产品。
- 不是 LLM Wiki Canvas 的第二个产品外壳。Qingyan Vault 是唯一面向用户的产品；LWC 的来源绑定、精确 Diff、冲突阻断和人工审查能力只作为可选 Strict Review 引擎。

## 产品结构

| 层 | 面向谁 | 默认能力 |
| --- | --- | --- |
| 人的工作区 | 普通 Obsidian 用户 | 收件箱、来源、知识、项目、知识地图、回顾 |
| Agent 工作区 | Codex、Claude、WorkBuddy 等 | 统一入口、草稿隔离、交接、反馈 |
| 可视化层 | 人 | Qingyan Vault Homepage、静态 Home、Bases、Canvas |
| 严格审核层 | 重要或批量改动 | 可选接入 LLM Wiki Canvas，不进入默认安装，不暴露工程术语 |

## 北极星

不是插件数量，而是：**下载者能否在 60 秒内完成一次捕捉，之后重新找到并使用它，同时让 Agent 的每次写入都可解释、可审查、可撤回。** 首发前以干净发行包、合成任务、故障注入和多宿主契约测试代替虚构用户证据；发布后再用下载、Issue 和可复现任务校正产品。
