# 用户使用手册

这套模板不要求你先成为知识管理专家。先走完一条最小路线，再根据真实使用增加结构。

## 1｜第一次打开

1. 下载整个文件夹，不要只下载其中的 Markdown。
2. 在 Obsidian 选择**打开本地仓库**，选择文件夹根目录。
3. 打开 [[Home|首页]]，完成[[开始使用|60 秒快速开始]]。
4. 暂时不要安装社区插件，也不要先搬入整个旧知识库。

完成标准：你创建了一条想法，把它连接到项目或知识地图，并从首页重新找到它。

接着完成[[Guides/把它变成你的|10 分钟个性化设置]]，用一个真实项目替换“只有演示、没有自己内容”的状态。

## 2｜每天怎么用

```text
有想法 → 放入 Inbox
有来源 → 写入 Sources
形成自己的判断 → 写入 Notes
要产生实际结果 → 连接 Projects
一个主题内容变多 → 创建 MOCs
每周重新使用一次 → Review
```

首页每天只回答四个问题：今天写什么、推进什么、重新使用什么、何时回顾。顶部“捕捉线索、写今天、知识总览、搜索”只调用本地插件和 Obsidian 核心能力；内容与首页在当前可见工作面轮换，不会把动作送到隐藏窗口。

- 点击“捕捉线索”后可直接输入，不需要切换编辑模式。
- 点击 Inbox 会从正文末尾继续写；点击项目下一步会定位到对应任务。
- “知识总览”只显示 Inbox、Sources、Notes、Projects 与 MOCs；指南和日记不会混入。

## 3｜每个目录放什么

左侧目录不是分类大全，而是一条知识成熟路径。顶层文件夹前的小印记帮助你快速辨认：**收**是 Inbox，**源**是来源，**知**是长期知识，**事**是项目，**图**是知识地图，**省**是回顾，**AI** 是尚未被人接纳的 Agent 工作区。印记只由本地 CSS 生成，关闭主题后文件夹名称和结构完全不变。

| 目录 | 应该放 | 不应该放 |
| --- | --- | --- |
| `Inbox` | 还没分类的想法和捕捉 | 已经成熟的长期知识 |
| `Sources` | 来源摘要、出处、关键片段 | 没有依据的模型推断 |
| `Notes` | 用自己的话形成的判断 | 整篇复制的文章 |
| `Projects` | 有完成标准和下一步的结果 | 永远不会结束的领域 |
| `MOCs` | 一个主题的导航和重要连接 | 原文副本 |
| `Review` | 日记、周回顾、验收 | 无期限堆积的任务 |
| `Agent` | Agent 草稿、交接和反馈 | 已被人接纳的正式知识 |
| `Archive` | 不活跃但仍值得搜索的内容 | 临时废纸 |

`Guides`、`Templates`、`Canvas` 与 `Attachments` 是辅助层。日常大多数时候只需要 Inbox、Projects 和 Review；不要为了让侧栏“看起来完整”而建立空目录。

## 4｜六种模板

新建笔记后打开命令面板（macOS `⌘P`，Windows/Linux `Ctrl+P`），执行 **Templates: Insert template**：

- `来源`：记录出处与可引用片段。
- `知识笔记`：形成自己的判断。
- `项目`：写清完成标准和下一步。
- `知识地图`：导航一个主题。
- `每日笔记`：按时间捕捉。
- `每周回顾`：重新使用知识并做 Continue/Hold/Archive 判断。

## 5｜三种找回方式

1. **知道名字**：使用快速切换 `⌘O / Ctrl+O`。
2. **记得内容**：使用全文搜索 `⌘⇧F / Ctrl+Shift+F`。
3. **只记得关系**：从反向链接、MOC 或 [[Canvas/夜航花园地图.canvas|Canvas]] 进入。

[[知识总览.base|知识总览]]适合筛选全部知识、进行中的项目和长期知识。它使用 Obsidian 核心 Bases，不依赖 Dataview。

## 6｜每周十分钟

1. 清理 Inbox：连接、改写、归档或删除。
2. 查看 Projects：每个活跃项目只留一个明确下一步。
3. 打开反向链接：找出没有进入任何主题或项目的孤立知识。
4. 写一条“本周知识库带回了什么”。
5. 只在真实痛点重复出现后考虑新增插件。

## 7｜让 Agent 帮忙

先让 Agent 只读解释，再授权单个文件或 `Agent/草稿/`。不要第一句话就要求它“整理整个知识库”。完整流程见[[Guides/Agent 使用手册|Agent 使用手册]]。

## 8｜迁移自己的内容

建议分三批：

1. 先迁入一个真实项目和五条以内知识，验证目录是否合适。
2. 再迁入一个主题的来源与 MOC，验证链接能否帮助找回。
3. 一周后才批量迁移旧材料；无法说明用途的旧内容先留在原处。

## 9｜常见误区

- 首页放满热力图、天气、倒计时和习惯，并不等于知识更容易复用。
- 标签越多不代表结构越好；链接应表达真实关系。
- Agent 自动生成大量摘要，会制造“看起来很懂”的知识债。
- Git、同步和 AI 插件都涉及额外权限，应在理解边界后单独启用。
