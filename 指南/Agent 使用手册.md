# Agent 使用手册

Agent-native 不是“让 AI 随意改 Vault”，而是让不同 Agent 共享同一套可读、可检查的文件协议。

## 1｜连接方式

| Agent | 推荐入口 |
| --- | --- |
| Codex | 把 Vault 根目录作为工作区；自动读取 `AGENTS.md` |
| Claude Code | 从根目录启动，先读 `CLAUDE.md` 和 `AGENTS.md` |
| WorkBuddy / Qoder | 选择根目录为工作区，显式引用 `AGENTS.md` |
| 其他文件型 Agent | 提示它先读 `AGENTS.md`，不要加载整个 Vault |

不要把 Vault 整体上传到未知在线服务。云端 Agent 是否能读取文件、连接网络或保留数据，应单独确认。

## 2｜四级权限

| 级别 | Agent 可以做什么 | 适用任务 |
| --- | --- | --- |
| R0 只读 | 搜索、解释、列出链接和缺口 | 第一次接触、问答、审计 |
| R1 草稿 | 只写 `Agent/草稿/` | 摘要、重组建议、多文件提案 |
| R2 定点写入 | 修改用户点名的文件 | 修正文案、补链接、更新项目状态 |
| R3 结构变更 | 重命名、移动、批量改写配置 | 需要明确范围、预览和人工验收 |

提交、推送、安装插件、联网同步和公开发布不属于上述权限，必须另行授权。

## 3｜标准工作流

### 第一步：只读定位

```text
先读 AGENTS.md、Home.md，以及与“夜航花园”直接相关的项目和来源。
不要修改文件。列出已有事实、推断、待验证和最小建议。
```

### 第二步：隔离草稿

```text
只允许创建 Agent/草稿/YYYY-MM-DD — 夜航花园回顾 — 草稿.md。
草稿必须包含：目标、读取范围、来源链接、建议正文、推断、待验证和建议落点。
不要修改知识、项目、知识地图或 `.obsidian/`。
```

### 第三步：人工接纳

人检查实际草稿和链接后，明确指定写入目标。不要仅凭 Agent 的完成摘要批准多文件修改。

### 第四步：验证与回读

Agent 运行 `./.starter-tools/self-check.sh`，然后列出修改文件、验证结果和仍需人工决定的事项。

## 4｜来源与推断规则

- 来源事实必须链接到 `来源/` 或用户点名的原始文件。
- 模型归纳标为“推断”，不写进来源正文。
- 证据不足标为“待验证”，不为了完整而补齐。
- 冲突来源并列保留，Agent 不替用户静默裁决。
- 摘要不能代替原始出处、日期和范围。

## 5｜上下文纪律

1. 从 Home、MOC 或项目入口开始，不全库扫描。
2. 先读索引，再读一层直接链接；不足时再扩大范围。
3. 报告实际读取范围和明确遗漏。
4. 长任务把临时正文放草稿，不把聊天历史复制到 Vault。
5. 跨会话才使用 `Agent/交接/`；任务完成本身不创建交接文件。

## 6｜反馈与记忆

人工纠正先记录到 `Agent/反馈/`。只有同一模式重复出现、用户确认它是长期规则时，才更新 `AGENTS.md` 或模板。私人事实、一次性偏好和原始聊天不进入共享规则。

## 7｜更严格的写入治理

当 Vault 变大、多人协作或 Agent 开始批量维护时，可选启用[[指南/严格审核|严格审核]]：底层使用 LLM Wiki Canvas 绑定来源、隔离草稿、检查冲突并生成精确 Diff。日常界面只使用“依据、改动建议、接受、退回”等语言；Qingyan Vault 不强制依赖它。

## 8｜完成报告格式

```text
结果：一句话说明完成了什么
读取：实际读取的文件或目录
修改：实际修改的文件
证据：运行的检查与结果
边界：未读取、未修改、未验证的内容
下一步：最多三个原子动作
```
